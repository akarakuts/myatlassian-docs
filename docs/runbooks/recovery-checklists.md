# my* Suite — Disaster Recovery Checklists

## Чеклист 1: Полная потеря сервера (P0)

### Подготовка (до инцидента)
- [ ] Бэкапы настроены и работают
- [ ] Облачное хранилище настроено (S3/GCS/Azure)
- [ ] Ключи шифрования сохранены в безопасном месте
- [ ] Документация актуальна
- [ ] Контактная информация обновлена

### Во время инцидента
- [ ] Оценить масштаб инцидента
- [ ] Уведомить команду
- [ ] Начать восстановление

### Восстановление
- [ ] Подготовить новый сервер
- [ ] Установить Docker и зависимости
- [ ] Клонировать репозиторий
- [ ] Восстановить конфигурацию (.env файлы)
- [ ] Восстановить БД из бэкапа
- [ ] Запустить сервисы
- [ ] Проверить работу всех сервисов
- [ ] Проверить целостность данных
- [ ] Уведомить о восстановлении

### После восстановления
- [ ] Записать хронологию инцидента
- [ ] Определить корневую причину
- [ ] Создать задачи для исправления
- [ ] Обновить документацию
- [ ] Провести ретроспективу

---

## Чеклист 2: Повреждение БД (P1)

### Подготовка
- [ ] Последний бэкап доступен
- [ ] WAL логи доступны
- [ ] Тестовое окружение готово

### Во время инцидента
- [ ] Остановить все сервисы
- [ ] Оценить повреждения
- [ ] Выбрать стратегию восстановления

### Восстановление
- [ ] Восстановить из полного бэкапа
- [ ] Применить WAL логи (если нужно)
- [ ] Проверить целостность данных
- [ ] Запустить сервисы
- [ ] Проверить работу приложений
- [ ] Проверить логи на ошибки

### После восстановления
- [ ] Записать хронологию
- [ ] Определить причину повреждения
- [ ] Настройить мониторинг БД
- [ ] Обновить процедуры бэкапа

---

## Чеклист 3: Частичный сбой сервиса (P2)

### Оценка
- [ ] Определить проблемный сервис
- [ ] Проверить логи сервиса
- [ ] Проверить логи БД
- [ ] Проверить использование ресурсов

### Восстановление
- [ ] Перезапустить сервис
- [ ] Проверить работу
- [ ] Если не помогло — проверить БД
- [ ] Если не помогло — восстановить из бэкапа
- [ ] Проверить зависимости сервиса

### После восстановления
- [ ] Записать хронологию
- [ ] Определить причину
- [ ] Настройить алерты
- [ ] Обновить документацию

---

## Чеклист 4: Потеря одного сервиса (P3)

### Оценка
- [ ] Проверить статус сервиса
- [ ] Проверить логи
- [ ] Проверить зависимости

### Восстановление
- [ ] Перезапустить сервис
- [ ] Проверить работу
- [ ] Проверить логи
- [ ] Уведомить пользователей (если нужно)

### После восстановления
- [ ] Записать причину
- [ ] Настройить мониторинг
- [ ] Обновить документацию

---

## Чеклист 5: Безопасность

### При подозрении на компрометацию
- [ ] Изолировать受影响ные системы
- [ ] Изменить все пароли
- [ ] Проверить логи доступа
- [ ] Проверить аудит-лог
- [ ] Уведомить команду безопасности
- [ ] Провести расследование
- [ ] Восстановить из чистого бэкапа
- [ ] Настройить мониторинг

### После инцидента
- [ ] Записать хронологию
- [ ] Определить вектор атаки
- [ ] Усилить безопасность
- [ ] Обновить процедуры
- [ ] Провести тренировку

---

## Чеклист 6: Мониторинг и алерты

### Ежедневная проверка
- [ ] Проверить статус всех сервисов
- [ ] Проверить логи на ошибки
- [ ] Проверить использование ресурсов
- [ ] Проверить бэкапы
- [ ] Проверить алерты

### Еженедельная проверка
- [ ] Проверить метрики производительности
- [ ] Проверить тренды
- [ ] Обновить документацию
- [ ] Провести тренировку восстановления

### Ежемесячная проверка
- [ ] Провести полный аудит безопасности
- [ ] Обновить зависимости
- [ ] Проверить план DR
- [ ] Провести ретроспективу
